# Build Blockwild

Create an ambitious Minecraft-inspired cooperative voxel sandbox for partyplay. This is a real exploration, mining, crafting, building and survival game. Working ID blockwild; title Blockwild. Follow MANAGER.md in this directory for ownership, coordination and references.

Target 2–10 connected players. Provisional view choice is first-person on each player's device (keyboard/mouse on desktop; dual-touch controls on phones/tablets) and a useful shared TV overview/spectator camera. The manager has asked the user about first-person devices versus TV split-screen and will forward any correction. Build renderer/rules independently of that routing choice. Do not silently turn Minecraft into an overhead block-placement minigame. Shared controller-scene readiness is a platform extension the manager owns; propose the smallest typed interface promptly.

Core required experience:
- An attractive seeded voxel landscape: hills, trees, water/shorelines, underground stone/ore and discoverable caves or landmarks. Use chunk meshes/visible faces and sensible view distance/quality; no Mesh object per terrain block.
- Responsive first-person movement/look, grounded collision, stepping/jumping, safe spawn and fall recovery. Desktop pointer lock only on a user gesture; explicit exit and usable touch controls. Aim highlight, reach/occlusion validation and coherent world units.
- Mine blocks with tool-dependent progress and feedback, pick up resources, place selected blocks authoritatively, inventory/hotbar and clear crafting recipes with meaningful wood → stone → metal progression. Building must support actual shelters and creative constructions.
- Day/night, health/food or an equally clear survival resource, original hostile creatures, combat feedback, respawn and recoverable setbacks. Offer a creative/free-build setting with relaxed resources and a survival setting. Keep early instructions gentle and interactive.
- Cooperative persistence during the room, reconnect without inventory/world loss, and deliberate world save/load or export/import with validation so meaningful builds can be resumed. Coordinate any server persistence API rather than inventing browser-only authoritative saves.
- A satisfying guided cooperative expedition goal alongside free building: exploration/resource milestones, a crafted beacon or other original shared objective, readable success/results and replay/new world. Do not force every sandbox session to end in a short timer; agree with the manager on host-finish/continue behavior.

Complete a playable slice first, then expand the world, material palette, crafting progression, creature behaviors, landmarks and polished UI. Use original voxel textures/material treatments, sunlight/fog, attractive sky/water and restrained particles; maintain clear scale and silhouettes. Gameplay feedback and camera feel take priority over decorative complexity. Music belongs to the user.

Networking is a design gate: do not broadcast the full voxel grid every tick. Propose bounded chunk/delta/revision synchronization with a reconnect baseline; keep player inputs and authoritative collision/hits separate from rendering. Protect 32 KiB inbound envelopes, bounded socket traffic and held-input rate. The existing 256 reliable actions per round is too small for unrestricted building: propose the concrete capability needed to the manager, or use carefully validated edge/hold inputs for repeated actions, with no duplicated mining/crafting on reconnect.

Write DESIGN.md with actual coordinate, camera, collision, networking, persistence and performance contracts. Own tests for terrain determinism, reachability, collision, mining/placing and inventory conservation, recipe validation, double submissions, two players targeting one block, stale edits, world serialization, disconnect, death/respawn and objectives. Browser QA must use real controls to mine → craft → build → survive/complete, plus min/max rosters, reload, A → other game → A and inspected first-person/TV frames. Measure render calls, frame distributions, world synchronization size/rate and control response. Add README and honest QA report. Do not stop at a pretty terrain demo.

## User scope clarification — 2026-09-08

Professional quality and sustained play are acceptance requirements. Blockwild is an open-ended sandbox: players choose what to explore, gather, craft and build; expedition goals remain optional and never end free play. The initial island is a vertical slice, not the final content target. Expand world variety/space, useful construction materials/tools and crafting/exploration depth after core controls pass. Persist worlds, communicate practical limits, and provide a deliberate save-version migration if dimensions/IDs change. Measure the larger world and realistic long-session edit counts with 10 players. Report the actual supported scope rather than implying unlimited Minecraft parity.


Survival sustainability acceptance: timber must be renewable for long building sessions. Add an explicit Grow tree action using acknowledged commands, Survival berry+earth cost (Creative free), authoritative reachable-ground and full-footprint checks, and atomic edit/resource updates. Grown trees persist through existing sparse edits. Preserve terrainVersion2 generation for existing saves; do not silently change its baseline.
